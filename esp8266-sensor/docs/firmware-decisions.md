## 1. 序列号生成规则（2026-04-30 确定）

**决策**：`场景前缀-5位随机hex`

格式：`{PREFIX}-{CHIP_ID_LAST_5_HEX}`

- 前缀由后端白名单控制：`DEMO-` `AIR-` `FAN-` `LIGHT-` `COLD-` `SENSOR-` `DHT22-`
- 随机部分取 `ESP.getChipId()` 后 5 位 hex（0~FFFFF，约 104 万种组合）
- 最终示例：`COLD-8A3F2`、`DHT22-B71C9`

**原因**：人工填后缀易重复（两个客户都填 "001"），芯片 ID 唯一且烧录时自动生成，约 100 万种组合足够避免冲突。

**注意**：
- 如果未来设备超 100 万台，可考虑 `millis()` 或 MAC 后 6 位
- 序列号唯一性由后端+数据库 UNIQUE 约束保障

## 2. 配网参数分工（2026-04-30 确定，2026-05-01 更新）

| 参数 | 谁定 | 怎么定 | 烧录还是配网 |
|------|------|--------|-------------|
| API Base URL | 开发者 | `config.h` 编译时写死 | ✅ 烧录 |
| 设备密钥 | **自动生成** | chipId 16 位 hex（8位原值+8位翻转） | ✅ 烧录 |
| 序列号 | **自动生成** | 场景前缀 + chipId 后 5 位 hex | ✅ 烧录 |
| WiFi 名+密码 | 客户 | WiFiManager 配网 | ❌ 配网填 |

**核心原则**：客户只需要填 WiFi 信息，其他全部自动生成。

## 3. 密钥生成规则（2026-05-01 确定）

**格式**：`{chipId_8hex}{chipId_翻转_8hex}` → 共 16 位

```
chipId = 0xA3F2B71C
翻转后 = 0x1CB72F3A
密钥   = "A3F2B71C1CB72F3A"  // 16 位
```

**原因**：
- 每台设备独立密钥，统一烧死有安全风险
- chipId 唯一，无需额外随机数生成
- 16 位长度安全级别适中
- 客户不感知、不记忆

## 4. WiFiManager 配网（2026-04-30 确定）

- 首次启动 → 自动进入配网 AP 模式（AP 名：`P008-Env-Monitor`）
- 长按 FLASH 按钮 3 秒 → 强制进入配网模式（重置 WiFi 配置）
- 配网页面只需要填：WiFi SSID + WiFi 密码
- 序列号等参数**不显示在配网页面**，烧录时已定

## 5. 量产烧录方案（待定）

> ⚠️ 以下为初步设想方案，待后续讨论确定后再实现。

### 批量烧录脚本

位置：`hardware/esp8266-sensor/scripts/bulk-flash.py`

**工作流**：
1. `python bulk-flash.py --generate 1000` → 后端预生成 1000 组（序列号, 密钥），导出 CSV
2. `python bulk-flash.py --list devices-20260501.csv` → 脚本从 CSV 取下一行烧录
3. 每烧完一台更新 `bulk-flash-state.json`（记录 `lastIndex`）
4. 下次运行从 `lastIndex + 1` 继续，不重复

**状态文件**：`scripts/bulk-flash-state.json`
```json
{
  "listFile": "devices-20260501.csv",
  "lastIndex": 17,
  "total": 1000
}
```

**恢复/重置**：
- `--reset`：从第 0 台重新开始
- 换 CSV 文件自动延续进度

### 脱机烧录器

- 先编译出 `.bin` + 预置序列号/密钥到 flash 指定地址
- 用 ESP8266 Download Tool 批量写入
- 一次可烧 8~16 块

### 当前阶段

开发/测试用 VS Code + PlatformIO 单台烧录即可。

## 6. 序列号/密钥来源（2026-05-01 确定）

**方案**：设备自生成（MAC + chipId HMAC-SHA256）

### 序列号

```
格式：{场景前缀}-{MAC地址后12位hex}
示例：DHT22-48E7DAA3F2B7
```

- MAC 地址全球唯一，无重复可能
- ESP8266 原生 `WiFi.macAddress()` 支持

### 密钥

```
算法：HMAC-SHA256(chipId, HW_SECRET)
输入：chipId(32位整数) + HW_SECRET(编译时写死)
输出：前 32 位 hex
```

- 一机一密
- 后端只需知道 HW_SECRET 即可校验，无需存储
- 拆机读 flash 只影响单台设备

### 为什么选这个

- 不要后端预生成 + 烧录注入 → 避免批量烧录脚本复杂度
- 不要纯粹随机密钥 → 后端需要存储
- 不要统一密钥 → 不安全
- ✅ HMAC + MAC → 零存储 + 唯一 + 一机一密

### 未来升级方向

- timestamp + nonce 防重放
- 每客户独立 HW_SECRET
- 证书认证（企业客户）
- OTA 远程升级验证逻辑
